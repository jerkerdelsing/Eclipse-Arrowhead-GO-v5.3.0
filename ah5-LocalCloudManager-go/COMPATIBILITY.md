# Compatibility and inherited restrictions

This relocation intentionally preserves the latest located manager's business behavior. New changes are packaging (standalone nested module/role-specific launcher), embedded UI fallback, documentation and tests. This is not a security remediation or full Java-equivalence implementation.

1. `PUT/DELETE /api/sysmonitor/subscriptions/{providerSystem}` currently checks confirmation and returns updated/removed flags **without forwarding a write**. Do not interpret this as applied configuration. This remains a release blocker.
2. `/api/intercloud` returns a static unavailable/no-relay summary. It does not inspect Gatekeeper/GateTunnel. Consumer cloud labels include hard-coded TestCloud strings; no live foreign authorization catalogue is queried.
3. Overview hard-codes registration/naming flags and leaves several collections empty. Subscription status hard-codes intake.connected=true/providerFound=false. These are display adapters, not authoritative readiness or security evidence.
4. Historian, SysMonitor, plant and orchestration adapters target the inherited Go-cloud routes/shapes. They are not proven compatible with the newer generic Go support port or latest Java APIs. The standalone module must be qualified against the providers actually deployed.
5. Console Host/Origin checks compare host names, not exact origins/ports. The `ah_console` cookie is not port-isolated and lacks Secure. Sessions/history are in-memory and reset on restart. Missing password disables APIs. Login lockout is global, five failures in five minutes then one-minute lockout; this is not comprehensive abuse protection.
6. The manager API is dispatched before the shared application's token/management checks. Its boundary is console password/session plus the transport's mTLS if enabled, not a bearer-token-only API. Static assets and health have no console session requirement. A proxy must preserve this intended boundary.
7. Authentication has explicit CN/profile pinning. Other provider clients use CA/SAN validation but do not generally pin expected provider CN. Do not claim universal authority-substitution resistance for this inherited code. Redirects are disabled. Optional CRLs reload for new connections only; omitted CRLs mean no revocation enforcement.
8. Lifecycle uses the static systemToCompose service allowlist and Compose-project filtered container list; MANAGED_SERVICES is not consumed by this implementation. Action is start/stop/restart only. Logs, however, can read any returned project container, not just the lifecycle allowlist. The raw Docker socket still confers broad daemon privilege: application checks are not a least-privilege socket boundary. Production needs a constrained proxy and deployment review.
9. Shared runtime source includes other roles for compile-time dependencies and inherited tests. The dedicated executable refuses selecting those roles; they are not a second support-system deployment. No Docker socket or live state is needed by tests.
10. Telemetry AMQP publisher has no durable local outbox; retries/reconnects do not establish exactly-once delivery. power=line/available and process health are generated status, not measurements of physical hardware. Registration is retried every20seconds; displayed registration flags are not confirmation. No real broker test is claimed here.
11. Shared state is the inherited JSON format, not the newer support port's transactional state model. There is no new Java SQL migration, encryption-at-rest or multi-process ownership guarantee. Keep independent state and backups.
12. Historical Markdown/SysML claims of three-way interchangeability are retained only under docs/legacy. The revised model and new SysD/SysDD/SD/IDD set distinguish intended common contracts from actual Go qualification.
13. The shared serviceOperations helper generates POST/name metadata for localCloudManagement and the legacy monitor service, whereas actual handlers include GET/PUT/PATCH/DELETE and nested paths. Registration metadata is therefore not an authoritative HTTP contract. The new IDDs document actual handler methods/paths; correcting advertised metadata is separate functional work, not silently folded into relocation.

Source relocation does not modify running containers or remove their deployment source. Before switching deployment build paths, close these gaps, qualify provider DTOs/policies, review Docker access, isolate browser trust domains, and test rollback.
