\section{Interface overview}
HTTPS with mandatory mutual TLS and JSON documents (bridge calls carry the target's media types). Management services need an identity token (\texttt{Bearer IDENTITY-TOKEN//<token>}) bound to the client certificate; bridges need \texttt{Bearer TRANSLATION-BRIDGE-TOKEN//<bridgeId>}. Errors contain errorMessage, errorCode, origin and timestamp. Request bodies are limited to 1 MiB.

\subsection{Bridge responses}
Status codes of the target are passed through. 401: missing or wrong bridge token; 403: method or path outside the negotiated operation; 404: unknown or ended bridge; 502: target unreachable or translation failed.
\subsection{Important delimitations}
TestTranslation is a test application system for the TranslationManager, not a production translator.
\begin{itemize}
\item One bridge kind: \texttt{generic\_https} to \texttt{generic\_https}, one negotiated operation per bridge; targets with \texttt{CERT\_AUTH} or \texttt{NONE} policies (authorization tokens for token-protected targets are not presented).
\item Data models \texttt{simpleJson} and \texttt{senml} only; translations are synchronous (a task is \texttt{DONE} or \texttt{ERROR} when \texttt{init-translation} returns).
\item Bridges are kept in the system's JSON state; translation tasks only in memory (latest 1000).
\end{itemize}
